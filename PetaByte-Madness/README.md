# PetaByte Madness

A first-person horror game on the M64 engine. Patrick Horner, a biologist in
an underwater lab, climbs onto the station's MRI and comes off it able to
raise **the scarlet veil** — a filter that shows him what is actually down
there with him.

The veil is the whole game, and it is built on one sentence:

> **The veil is not a filter. It is a palette swap.**

Author both states offline; at runtime change only which lookup table you
point at. That costs 32 bytes of DMA per material and shades zero extra
pixels, where the obvious version — a full-screen alpha-blended red
rectangle — costs 76,800 read-modify-writes against the colour buffer every
frame and is the single most expensive thing you can ask an RDP to do.

And it must not be free in the fiction, so: **while the veil is up, they can
see you too.** Every demon's behaviour is a consequence of that one line.

`docs/VEIL_DESIGN.md` is the spec. Read it before touching `src/pm_veil.*`,
the same way `compass_artifact_*.md` is the spec for the build system.

## Build and run

```bash
nix build .#petabyte-madness      # -> result/petabyte-madness.z64
nix run .#ares -- result/petabyte-madness.z64
./dev shot petabyte-madness out.png
```

Controls: main stick moves, C-stick looks, R sprints, **Z raises the veil**
(held, not latched — the design is about managing when it is up).

## Where this stands

Slice 0 is the mechanic end to end, which is the part worth proving before
any art goes in:

- `src/pm_veil.*` — the veil runtime. Phase machine, quantised 9-step
  crossfade, fog + far-plane rebate through `M64Scene`, TLUT bind, the
  phantom body gate, the vignette ring.
- `src/pm_demons.*` — the four demons as `m64_actor` profiles, each
  implementing its species rule (see below).
- `src/pm_hud.*` — the HUD, whose only job is to make the veil's *cost*
  legible: air, "SEEN", and whether your toggle is still yours.
- `assets/pm_lab.map` — one flooded corridor with six statue plinths, two of
  which are not statues. Generated by `tools/gen_lab_map.py`.

| demon | rule |
|---|---|
| **IMP** | Knows exactly where you are the moment you resolve it. The teaching enemy. |
| **HELLHOUND** | Only *moves* while the veil is down. Veil up and it freezes where it is — visible, motionless, nearer than it was. |
| **GARGOYLE** | Only ambushes what has looked at it. Veil down it is one of the plinth statues; veil up the statue is gone. |
| **OVERLORD** | Pins the veil ON inside its halo. It cannot blind you, only expose you — and take the tool you manage everything else with. |

### Not built yet, roughly in the order it should land

1. **The CI4 + TLUT bake** (`VEIL_DESIGN.md` §8 steps 1–2 — "this is the
   real work; everything else is an afternoon"). No baked ramps exist, so
   `pm_veil_bind_palette` has nothing to point at and the visible half of
   the veil today is fog + far plane + the phantom body gate.
   `pm_veil_ramp_build` builds a ramp at boot from a cold/veiled palette
   pair as a stand-in; swapping to baked ramps is a change of one pointer,
   not of any call site.
2. **Demon animation.** `gltf_to_t3d` reports `Channel target not found` for
   every channel in all four `.glb` files and drops them — they are node
   animations on an unskinned hierarchy, and the importer wants a skin. The
   static meshes convert cleanly.
   **The fix is known and already proven on the centaur:** rebuild as an
   armature with rigid one-bone-per-vertex groups and the animations survive
   intact. See `docs/ASSET_PIPELINE.md`; `tools/blender/centaur.py` is the
   worked example.
3. **Audio.** `veil.dsp` is described in `VEIL_DESIGN.md` §7 but was not in
   the asset drop. The architecture it wants — world ambience baked twice
   and crossfaded on mixer gain, demon voices run live — is exactly the two
   paths `nix/faust.nix` already implements. `pm_veil_audio_t()` is the hook.
4. **Combat, damage, the LOACH, Horner as a viewmodel.**

## Layout

```
Makefile              mirrors game/Makefile — n64.mk, t3d.mk, m64.mk, in that order
src/                  the game
assets/               what ships in the ROM (models, rig, map, textures)
docs/                 VEIL_DESIGN.md is the spec; ASSET_PIPELINE.md is how art gets in
tools/                the asset generators, mc_rig_export.py, gen_lab_map.py
reference/            F3DEX2 dumps — reference data, not built
vendor/               candidate engine subsystems, not yet wired
archives/             the original drops, gitignored
```

Model authoring lives at the repo root, alongside the other games' scripts:
`tools/blender/centaur.py` (the rig), `tools/blender/pm_props.py` (everything
OBJ/glTF-sourced), `tools/blender/objkit.py` (the parsers — no `bpy`, testable
with a bare `python3`).


## Boot

```
M64 SPLASH   the DeMoD mark — engine-level (engine/src/m64/m64_splash.h),
             a 3D wordmark assembling to a Faust jingle. Any button skips.
TITLE        skull over the drone flyover
ATTRACT      after ~12 s idle
FILE         3 profiles; an empty one starts the intro
```

The splash is a publisher mark, not this game's, so it lives in the engine
and Ganja Goblin can adopt it with four calls. Its two assets
(`tools/blender/m64_logo.py`, `dsp/m64_jingle.dsp`) are built at the flake
level and passed in as handles; both are optional and the timing is
identical without them.

**The picture is timed to the sound, not the reverse.** The jingle's chord
resolves 1.25 s in; the logo finishes assembling and the screen flashes on
that same frame. Audio cannot be nudged a frame at runtime and geometry
can, so the sound is the master. Move one, move all three — they are one
constant in `m64_splash.c`.

## Two DFS conventions, and one of them bit

`assetLib.mkSound` writes under `sfx/`. `faust.mkBakedInstrument` writes to
the **DFS root**. Mixing them up produces silence, not an error — a failed
`m64_sfx_load` just means the game runs quiet. The ambience bed was loading
from `rom:/sfx/pmdrone.wav64` for a while and finding nothing.

| builder | lands at | used for |
|---|---|---|
| `mkSound` | `rom:/sfx/<name>.wav64` | authored WAVs (everything in `pm_sfx.h`) |
| `mkBakedInstrument` | `rom:/<name>.wav64` | Faust bakes (the drone, the jingle) |

## Spoiler policy

Three reveals, in order, and the code is built to protect each one:

| reveal | first seen | protected by |
|---|---|---|
| **the centaur** | the beach, at the end of the intro | the attract reel's last shot is locked behind `PM_FLAG_SEEN_REVEAL`, set when a profile finishes the intro |
| **the veil** | mid-game | appears nowhere in the title, the attract reel or the intro — it is not raised, drawn or mentioned before PLAY |
| **the demons** | mid-game, with the veil | never drawn outside PLAY; the attract reel's lab shot is an empty room |

The attract reel's shot order is load-bearing: the centaur is **last**,
because the lock works by shortening the reel by one. Adding a shot after
him unlocks him by accident.

## Sound

`PetaByte-Madness/src/pm_sfx.h` is the contract. Every sound is a named id
already wired to its trigger; a missing file is silent, not an error, so
the beats can be timed against the animation before any audio exists.

To make one real:

1. drop a mono WAV at `PetaByte-Madness/assets/sfx/<name>.wav`
2. add `pmSfx "<name>"` to the ROM's `assets` list in `flake.nix`
3. nothing else — the id is already fired at the right frame

The ambience bed is different: it is a baked Faust instrument
(`dsp/pm_drone.dsp`), looping on its own mixer channel, ducked per screen.
